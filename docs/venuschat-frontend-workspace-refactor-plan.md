# VenusChat 前端工作空间重构方案

状态：2026-09-29 确定，交由 Luna Max 实现。本文是实现边界和验收标准。

## 1. 目标与技术选择

当前 `ChatView` 同时承载私人聊天、团队派活、项目列表和混合任务面板；项目中心、团队协作、团队身份又散落在不同入口。重构后的第一眼必须回答用户三个问题：**现在在哪个空间？当前团队项目是什么？下一步该做什么？**

继续使用 **Tkinter + 现有 `theme.py` / `widgets.py`**。维持当前暖白底色、陶土红强调色、字体、圆角控件、消息气泡和窗口装饰。新的库或语言会同时引入启动、打包、凭证和渲染迁移；这次问题的核心在导航与信息架构，保留现有技术栈更容易完整落地并保持视觉一致。

本次交付是**可运行的前端重构**，不止换标签、移动按钮或画设计稿。保留现有后端 API、个人/团队隔离、身份入队、项目权限、Worker 管理和版本审阅能力。当前工作区已有未提交修复，必须在其上增量修改，禁止重置或覆盖。

## 2. 新的信息架构

```text
全局顶栏：品牌 | [个人空间] [团队空间] | 当前连接/模型 | 设置

个人空间
├─ 左侧：新建对话、最近对话、个人项目、个人任务入口
└─ 主区：私人聊天与输入框；个人后台任务只在个人入口显示

团队空间
├─ 左侧：团队名、当前项目选择器、任务、版本与审阅、成员、项目管理
└─ 主区：随左侧选择切换
   ├─ 任务：派发团队任务、项目任务列表、任务详情/提交变更
   ├─ 版本与审阅：变更列表、提交 SHA/差异、投票及合并
   └─ 成员：项目成员/设备摘要、进入邀请与管理

设置
├─ 团队与成员：Hub 连接、入队申请、管理员审核、设备状态
└─ 项目中心：创建、认领、邀请、归档、治理等管理操作
```

团队空间的主页面是**任务工作台**，不显示“新建对话”“最近对话”和普通聊天气泡。个人空间不显示团队变更、团队成员和团队任务列表。全局顶栏的两个空间按钮始终可见，包括用户打开设置时；没有加入 Hub 时，“团队空间”进入清楚的连接引导，不假装已连接。

### 顶栏与侧栏

- 顶栏用两个明确命名的入口“个人空间”“团队空间”替代需要猜测方向的“进入某团队 → / ← 切回个人对话”。活动空间有选中样式，并同时显示短文本状态，例如“个人 · 本机”或“团队 · VENUSDEMO”。
- 团队侧栏固定显示当前项目名、角色、项目状态；项目可切换时用现有 `SelectField` 或同风格控件。项目选择必须由 Hub 确认后才更新 UI。
- 团队侧栏常用入口仅三个：“任务”“版本与审阅”“成员”。“项目管理”通往现有项目中心；“团队连接”通往设置中的团队与成员。不要在个人侧栏重复出现这些入口。
- 所有入口使用同一套名称；项目中心中仍可保留管理类操作的完整窗口。避免出现两个“团队协作”按钮和多个意义不明的“任务面板”。

### 个人空间

- 保留已有私人聊天体验、历史、草稿、模型和 Agent 选择器。
- 后台个人任务设单独可见入口或抽屉，只显示当前个人后端、当前用户的私人任务。个人长任务/个人项目功能继续可用。
- 从团队切回个人时恢复原会话和草稿；团队数据不进入私人会话历史。

### 团队空间 · 任务

- 顶部为当前项目标题、状态、本人角色、Hub 连接状态。任务发布区明确写“派发团队任务”，提示“项目成员可见 · 后台执行 · 归属当前项目”。用户在这个专用输入框**直接写任务正文**；前端调用现有 `BackendBridge.dispatch()`，无需让用户记住 `!` 语法。保留旧 `!` 输入兼容，但不把它作为团队页面的唯一入口。
- 下方只显示**当前项目**的团队任务。卡片至少有标题、状态、发起人、时间、项目、进度；可按“全部 / 我发起的 / 进行中”筛选。选中任务显示结果、错误、操作。
- “提交变更”只在自己的、已生成改动的团队任务上出现；使用现有指定路径提交弹窗。任务失败、排队或没有文件改动时给出原因和下一步。
- 不把 Worker 任务与 Agent 任务混为同一队列。Worker 管理保留独立入口并清楚标记“Worker”。

### 团队空间 · 版本与审阅

- 在团队主界面内展示当前项目的仓库状态、变更列表、提交 SHA、文件差异、`已通过/需要`票数和当前状态。沿用现有 `team_collab_view.py` 的请求及权限逻辑，可抽取可嵌入的 `Frame`，原弹窗入口保留为兼容壳。
- 审阅动作按状态显示：作者看到“不能审阅自己提交的变更”的解释，不给可点击的批准按钮；有资格的其他成员可批准/拒绝；未达到票数时“合并”不可用且说明原因。服务端仍是最终授权方。
- 版本库未初始化时显示共享路径初始化引导；项目待认领时引导认领；归档项目只读。冲突、基线过期、票数失效要显示原始原因和可执行的下一步。

### 团队空间 · 成员

- 以只读概要展示当前项目成员、本人角色和获准终端数；有管理权限时提供“邀请或管理成员”按钮，进入项目中心的对应区域。
- Hub 团队成员入队、设备审批继续在“设置 → 团队与成员”；在本页清楚写明“加入 Hub”和“加入项目”是两步，避免把 Tailscale 组网误认为项目授权。

## 3. 状态模型与安全边界

- 只有一个活动后端客户端，但 UI 将其解释为 `Personal` 或 `Team` 工作空间。活动空间由**当前已验证的 origin**和已加入的 Hub 连接推导，不能仅靠按钮本地布尔值。
- 每个 origin 分别保存会话选择、草稿和当前项目。切换空间时立即清空上一个 origin 的会话、任务、项目和差异画面；异步返回继续沿用 bridge epoch/请求代际检查，不允许旧结果覆盖新空间。
- 团队任务和变更再按 `project_id` 过滤。切换项目时先清空旧项目列表与详情，等待 Hub 确认；失败则保留原项目并显示错误。无项目时禁用派活和审阅，提供“选择/加入项目”入口。
- 四类页面状态有明确内容：未连接 Hub、申请中/待领取、已连接但无项目、已选择项目。另有离线/凭证失效状态，禁止显示旧缓存当作当前内容。
- API 仍为后端的 `/api/v1/jobs`、`/api/v1/projects`、`/api/v1/projects/{id}/changes` 等；保留设备 token 的现有安全存储和 Tailscale Serve 认证流程。前端不会绕过服务端权限或降低审批阈值。

## 4. 代码边界与实施顺序

1. **抽取语义状态**：在独立模块中实现空间/项目视图状态和纯函数过滤器，集中处理空间切换、任务范围、当前项目和空态。把与 Tk 控件无关的判断从 `ChatView` 移出。
2. **重排应用壳**：在 `app.py` 顶栏增加常驻空间切换与状态；应用根容器分别承载个人 `ChatView` 和新的团队工作台。设置仍是独立页；它返回时恢复之前的工作空间。
3. **收敛个人页**：`ChatView` 专心处理私人会话和个人任务。保留原消息渲染、流式回复、Agent/模型控件；移除团队项目/审阅的主入口和团队任务混排。
4. **建立团队工作台**：新增 `team_workspace_view.py`（可继续拆为 task、changes、members 组件）；用现有 `ApiClient`/`BackendBridge` 异步请求，不能阻塞 Tk 主线程。团队任务发布、项目切换、任务列表、变更审阅都在此处组织。
5. **复用管理窗口**：`ProjectHubWindow` 负责创建/认领/邀请/归档/治理；`SettingsView` 负责 Hub 身份。不要在主工作台再复制一整套表单。必要时给管理窗口加可选的初始项目或定位区域参数。
6. **收尾与文档**：统一按钮文案、空态和禁用态；更新 `docs/venuschat-本机Hub-4分钟团队模式录制稿.md` 的录屏路径和词稿，使它与新界面一致；更新过时的结构性前端测试。

技术实现可以调整模块拆分，但**最终界面结构与功能边界**按第 2、3 节验收。开发中不得重启或改写用户当前运行的 `8001`、`8003`、Tailscale Serve，也不得触碰凭据。

## 5. 视觉与响应布局规范

- 只使用现有 `theme.py` 色板、字体和 `FlatButton` / `SelectField` 等风格控件；不引入另一套图标或设计语言。
- 主窗口最小 `1120 × 700`：左侧导航与主内容最多构成**两块常驻区域**；任务详情或变更差异在主内容中切换/展开，避免再常驻第三列。宽屏可以放大留白和差异区域。
- 保持清楚的层级：页面标题 → 当前项目及状态 → 主操作 → 列表/详情。网络状态、角色和审批票数要用文字显示，颜色只作辅助。
- 弹窗、长列表和版本差异在 `1120 × 700` 下可滚动，底部主按钮不能被遮住。键盘焦点应落在任务正文或当前可执行的控制上。
- 视觉验收至少覆盖 `1120 × 700` 与约 `1500 × 900` 两种窗口尺寸的个人、团队任务、变更审阅和无项目状态；检查溢出、重叠与空白浪费。

## 6. 验收场景

1. 个人聊天中输入普通问题，生成回复并保留草稿/历史；切团队再切回，个人会话不变。
2. 团队工作台没有私人聊天入口；选中活动项目后直接输入任务正文并派发，后端收到 team visibility 和准确的 `project_id`。
3. 个人任务只出现在个人空间；团队任务只出现在对应项目。快速切换空间、快速切换项目以及旧请求晚返回时，画面没有跨空间/跨项目残留。
4. Hub 离线、凭证失效、申请待批、未选项目、待认领、未初始化版本库、项目归档都有可理解的状态和下一步；禁止误点无效动作。
5. A 提交变更后不能批准自己；B 在另一设备上查看相同 SHA 和差异并批准；达到配置票数后可合并。票数不足时仍显示等待。
6. Hub 团队邀请、审批、设备领取，项目创建/认领/邀请，Worker 入口和设置页仍能按原权限使用。
7. 运行相关前端契约、上下文切换、项目归档、版本审阅测试；对新纯状态逻辑增加有意义的单元测试。旧测试如断言混排布局文本，改为断言新信息架构，不保留过时断言以求表面通过。
8. `python -m compileall src/venuschat_v1`、相关测试及 `git diff --check` 通过；视觉检查能看到第 5 节描述的布局。
