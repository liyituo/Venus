# VenusChat 本机 Hub：4 分钟团队模式录制稿

> 本次只用一台 Windows 电脑：个人后端在 `127.0.0.1:8001`，隔离团队 Hub 在 `127.0.0.1:8003`，VenusChat 通过 Tailscale Serve 的 HTTPS 地址连接本机 Hub。视频从上一段个人 Agent 演示接入。服务启动、Tailscale 状态核对和密钥处理全部在录制前完成。

## 录制前准备（不入镜）

- 打开 VenusChat，确认顶栏能切换“个人空间 / 团队空间”；团队空间能选 `DEMO`，状态已连接，任务按钮可用。
- `DEMO` 已认领，版本库已初始化，共享范围是 `readme.md`。目前只有负责人一位成员，所以本片**介绍审阅功能，但不演出第二人批准或合并**。
- 这套隔离演示 Hub 仅在**只有一位有效成员**时把 **Agent 工具操作确认**设为单人一票，方便同一台电脑完成真实任务；第二位有效成员加入后会自动恢复多人操作确认。Hub 设备身份与项目权限始终有效。**文件版本审阅**仍禁止作者批准自己的提交，本片只展示到待审。
- 复现此单人流程时，先备份隔离 Hub 数据目录的 `.venus/collab_config.json`，再在其中保留 `"team_mode": true` 并设置 `"single_member_demo_confirmations": true`，重启带 `--isolated` 的 Hub。该选项默认关闭；普通 Hub 不接受单人例外。
- 把下面的任务正文复制到剪贴板。若 `录屏-01` 已用过，改成 `录屏-02`，并同步修改提交目的。
- 录制软件只截 VenusChat 窗口；遮住完整 Hub 域名、VI/VN 设备码、邮箱和任何一次性代码。将窗口调到能同时看清左侧导航与主内容的大小。
- 允许真实任务花时间完成，后期剪掉等待。保留“派发成功 → 任务完成”的真实画面；若没有生成文件改动，就重新试跑，不演出提交成功。
- 确认操作只有约 120 秒处理时间。看到“等待确认”就立即在任务详情点“处理待确认操作”，核对工具名称、目标路径和差异后再决定是否允许。当前演示 Hub 的操作确认只需一票；若已超时，这条确认无法补批，须重新派发任务并把 `录屏-01` 换成新的编号。

## 4 分钟分镜与台词

方括号内为动作，不读出来。时间是成片长度，可在等待任务时使用跳切。

### 0:00–0:35｜本机 Hub 与连接

**镜头**：从个人空间点顶栏“团队空间”；停 2 秒。点团队侧栏下方“团队连接与成员审批”，只拍“已加入”和 Hub HTTPS 地址的开头，不展示完整设备码。随后点顶栏“团队空间”返回。

> 刚才演示的是个人 Agent。现在我切到团队空间。这台电脑同时运行个人后端和一个隔离的团队 Hub；客户端通过团队 HTTPS 地址连接 Hub。这里已经完成设备身份验证，所以能进入团队项目。将来其他成员接入时，也会先经过团队身份和设备审批。

### 0:35–1:05｜项目中心与权限

**镜头**：左侧“当前项目”选择 `DEMO`，显示负责人角色。短暂点击“项目管理”，展示项目列表和管理入口，关闭窗口回团队页；避开一次性代码区域。

> 团队工作先选项目。我现在是 `DEMO` 的负责人。项目中心负责创建、认领和邀请成员；加入 Hub 与获得这个项目的访问权限是两步，所以项目任务不会自动向整个网络开放。

### 1:05–1:45｜三个页面与 Worker 边界

**镜头**：依次点左侧“任务”“版本与审阅”“成员”。在版本页停留，让观众看到“版本库已初始化”和共享范围 `readme.md`；成员页只拍角色，遮住设备名称。回“任务”，向下滚动，指一下“Worker 任务与审批 / 本机 Worker 授权”，不点击授权。

> 团队空间主要有三个页面：任务页看派发和进度，版本页看文件差异和审阅，成员页看项目权限。当前版本库只共享 `readme.md`。下方的 Worker 入口用于另一条设备派活队列；我现在演示的是上方的 Agent 团队任务。

### 1:45–2:35｜派发一项真实任务

**镜头**：在“派发团队任务”粘贴下方正文，停 2 秒，再点“派发到此项目”。展示当前项目任务列表。若出现“等待确认”，点“查看待确认任务”→任务详情“处理待确认操作”，看清目标路径与改动后点“允许”；保留弹窗与点击画面约 5 秒。任务完成前的等待用跳切缩短。选中已完成任务，拍到结果和“提交变更”。

> 我把目标文件和完成标准交给 Hub。任务归属 `DEMO`，我可以在这个页面跟踪进度。如果 Agent 请求修改文件，我会先核对这次操作再允许它继续。任务完成后，文件变更仍需要明确提交到项目版本审阅。

**粘贴的任务正文：**

```text
请只修改当前团队项目共享的 readme.md。在末尾新增“本机 Hub 演示 · 录屏-01”小节，写一句“团队任务归属项目，文件变更经过审阅后才能合并。”不要修改其他文件；完成后说明实际修改的路径。
```

### 2:35–3:15｜指定路径提交与版本差异

**镜头**：点任务详情“提交变更”；“变更目的”填 `录屏-01：本机 Hub 团队演示`；点“读取任务改动”，确认“提交路径”只有 `readme.md`，然后点“提交审阅”。提交成功后可能自动打开项目版本窗口；关闭它，回团队页点“版本与审阅”→“刷新”，选目的含 `录屏-01` 的新变更，展示差异、SHA 和票数。不要误选旧草稿。

> 这里我只选择 `readme.md`，提交范围一目了然。版本页会显示这次提交的 SHA 和实际差异。前面演示的确认弹窗针对 Agent 的一次操作；这里的审阅针对一份具体的文件版本。

### 3:15–3:40｜成员审阅怎么运作

**镜头**：让“待审”、当前票数以及“你是此变更的作者，不能审阅自己的提交”同时入镜；再短暂切到“成员”页，指一下“邀请或管理成员”。**不要点批准、合并，也不要假装已有第二位成员。**

> 目前这个本机演示项目只有我一位成员，所以变更会停在待审状态。作者不能批准自己的提交。以后邀请另一位成员加入项目后，对方可以核对同一份 SHA 和差异；批准票数达到要求，负责人才能合并。

### 3:40–4:00｜回到个人空间

**镜头**：点顶栏“个人空间”，打开刚才的个人对话，停留 3 秒结束。

> 最后切回个人空间，刚才的私人对话仍在；团队任务、版本和成员权限留在 Hub 项目里。这就是一台电脑上可以完整展示的团队工作台，双人审阅则在第二位成员加入后继续。

## 剪辑时只检查这五件事

1. 总长控制在 **4:00 以内**；任务运行的等待剪短，保留真实派发和完成结果。
2. 镜头每次切页后停 1～2 秒，观众要能看清 `DEMO`、`readme.md`、新变更目的、差异和“待审”。
3. 不出现完整邀请码、认领码、邮箱、设备标识或模型密钥。
4. “批准”和“合并”只作功能介绍；当前单成员状态下不宣称已经完成。
5. 如果任务没有改出 `readme.md`，删掉提交镜头并改为展示已有版本记录；口播只说“这里可以指定路径提交”，不要说“这次已经提交”。
